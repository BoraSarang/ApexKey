# RESEARCH 2026-11-20 — Alfred 6 업데이트 조사

> status: **조사 완료 (2026-11-20)**
> 질문: "Alfred가 6으로 버전업했다. 무엇이 바뀌었고, ApexKey에 의미가 있나."
> 범위: Alfred 6.0~6.0.2 공식 릴리스 노트·소개 페이지·Alfred UI 문서·라이선스 안내. **코드 변경 없음.**
> 방법: 1차 출처(alfredapp.com 공식 페이지)만 사용. 벤더 주장은 "벤더 주장"으로 표기.
> 한계: 실제 설치·성능 측정·가격 할인액 확인은 하지 않았다. §6 참조.

## 0. 결론 먼저

**Alfred 6은 "런처의 기능 추가"보다 "워크플로 개발 플랫폼"에 가까운 업데이트다.** 핵심은 JSON으로 네이티브 UI를 만드는 **Alfred UI 툴킷**이고, 나머지는 환경설정·테마·연락처·검색 기록·클립보드의 정비다.

ApexKey 관점:

- **직접 경쟁 기능은 없다.** Alfred 6에도 "전면 앱의 메뉴바 메뉴를 검색·실행"과 "트랙패드 에지 슬라이더"는 없다. ApexKey의 니치는 그대로다.
- **포지셔닝은 오히려 ApexKey와 같은 방향을 강화했다.** 100% 네이티브, DMG 약 6MB, 로컬·프라이버시, AI는 선택(워크플로) — ApexKey의 "가볍고 로컬" 원칙과 일치한다. 다만 Alfred는 이 메시지를 훨씬 잘 팔고 있다.
- **기능 동결 원칙상 채택할 것은 없다.** Alfred UI는 워크플로 생태계용 도구라 ApexKey에 이식할 대상이 아니고, 나머지는 ApexKey에 이미 있거나(최근 항목·클립보드 기록·테마) 제품 범위 밖(연락처·파일 검색)이다.
- **결론: 대응 불필요. 관찰만.** 다음 릴리스에서 macOS 27 호환·테마 쪽 변화가 나오면 그때 ApexKey의 macOS 27 동작과 비교한다.

## 2. 주요 변경 — 5묶음

### 2.1 Alfred UI 툴킷 (핵심)

JSON 기반·이벤트 드리븐·네이티브 UI 툴킷. 컴파일 없이 `.alfredui` 패키지의 `ui.json`을 읽어 AppKit 뷰를 즉석 생성한다.

- 컴포넌트: 레이아웃, 라벨, 버튼, 체크박스, 피커, 텍스트 필드, 비밀번호 필드, 텍스트 영역, 마크다운, 진행 바, 이미지, 데이터 뷰, 웹 뷰
- 템플릿으로 재사용 컴포넌트 구성, 변수·이벤트·액션·`pulse`(주기 스크립트)·디버그/로그 지원
- UI를 실행 중에 수정, 글래스 스타일 선택, 알림·파일 대화상자·사운드·음성·컨텍스트 메뉴
- Alfred 안에서 실행하거나 **Dock 아이콘이 있는 외부 앱 창**으로 열기. 여러 UI 동시 열기, 창 레벨/타이틀바 설정
- 공식 예: 스크립트 없이 몇 KB의 JSON으로 동작하는 웹 브라우저

의미: Alfred가 "검색 결과 목록" 앱에서 **워크플로 저자가 네이티브 UI를 조립하는 플랫폼**으로 확장했다. 다만 이는 **Alfred 생태계 안의 개발자 도구**다.

### 2.2 환경설정·테마

- 환경설정 전면 개편: macOS 27 기준 정돈, **라이트 모드 완전 지원**(워크플로 편집기 포함), 리퀴드 글래스 요소, 실행 속도 개선
- 상단 "Sections" 메뉴 추가(좌측 사이드바 숨김 상태에서도 섹션 이동)
- 새 기본 테마: Alfred 6 라이트/다크, macOS 라이트/다크, Purple Ribbon. 오래된 테마는 제거(추후 아카이브 배포 예정)
- 창 블러 모드 분리: 창 외관(라이트/다크)과 시각 효과 모드. 배경색 기반 "Automatic"
- 창 페이드 인 옵션(기본 꺼짐 — 성능 우선)

### 2.3 검색·데이터

- **연락처 검색 전면 교체**: 내부 최적화 검색으로 대폭 빨라짐(벤더 주장), 기본 결과에 연락처 사진 표시, 새 워크플로 객체 2종, Spotlight 기반 검색 제거
- 발음·분음 부호 검색 개선, **CJK 단어 분할**, 임의 단어 순서 검색
- **쿼리 히스토리**: 일시적/영구적 기록 선택, ↑ 버튼으로 호출, 보존 기간 24시간~3개월, `!` 키워드로 검색
- **대체 검색(fallback)을 무료 사용자에게 개방** — DuckDuckGo 등을 기본 fallback으로

### 2.4 클립보드·마크다운·자동화

- 클립보드 뷰어 최대 **30개** 항목, 항목 수·미리보기 글자 크기 설정 가능
- 마크다운: **표 렌더링**, GitHub 스타일 `[!NOTE]` 인용, 링크 강조색/밑줄 제거
- 자동화 작업(230개 이상) 설정에 **검색** 추가
- "Terminal Command" 객체가 터미널을 백그라운드로 띄워 Alfred 블로킹 방지

### 2.5 기반·접근성

- macOS 알림을 `UserNotifications` API로 전환
- 접근성 레이블 대폭 보강, 온보딩·권한 요청 흐름 개선
- 계산기 수학 파서 deprecation 정리, 아이콘 스쿼클 해제, 웹 검색 아이콘 갱신
- `strictmods`, `iconresize` 등 Script Filter JSON 확장

## 4. ApexKey 관점

### 4.1 카테고리 비교

| 항목 | Alfred 6 | ApexKey 1.9.0 |
|---|---|---|
| 주 진입점 | 키보드 런처(키워드 입력) | 전역 핫키 → **전면 앱 메뉴 실행** |
| 핵심 확장 | 워크플로 + Alfred UI(JSON) | 워크플로 단계 + 154종 액션 카탈로그 |
| 입력 소스 | 키보드 | 키보드 + **트랙패드 제스처/에지 슬라이더** |
| 파일·웹·연락처 검색 | 강점 | 범위 밖(빠른 실행 정도) |
| 클립보드 기록 | 강점(30개) | 팔레트에 통합 |
| 테마 | 풍부한 기본 테마 + 편집기 | 커스텀 테마 시스템(라이트/다크) |
| 배포 크기 | 약 6MB | 디버그 빌드 42MB(릴리스는 더 작음) |
| 가격 | £40/£70 | 무료 + MIT |
| 최소 macOS | 12+ | 14+ |

**겹치는 부분**은 "핫키로 호출하는 생산성 도구", "워크플로/액션 실행", "클립보드 기록" 정도다. **다른 부분**이 ApexKey의 정체성이다 — 타 앱 메뉴를 직접 실행하는 것과 트랙패드 입력.

### 4.2 이번 업데이트로 바뀌는 것

- ApexKey의 기능적 우위/열위는 **변하지 않는다.** Alfred 6은 ApexKey가 하는 일(메뉴 실행, 트랙패드)을 하지 않는다.
- Alfred UI는 ApexKey에 **이식 대상이 아니다.** ApexKey에는 서드파티 워크플로 생태계가 없고, 제품 방향도 "가벼운 메뉴바 상주"다. UI 툴킷을 넣는 순간 앱이 플랫폼이 된다.
- Alfred의 "네이티브·경량·로컬·선택형 AI" 메시지는 ApexKey의 기존 원칙과 같다. **경쟁 압력은 기능이 아니라 인지도/온보딩에서 온다.** 이는 이번 조사로 새로 생긴 결론이 아니라 기존 방향(진입장벽 낮추기)의 연장이다.

### 4.3 기능 동결 원칙에 따른 판단

| Alfred 6 변경 | ApexKey 채택 | 이유 |
|---|---|---|
| Alfred UI 툴킷 | ✗ | 생태계 플랫폼 기능. 동결 범위 밖 |
| 쿼리 히스토리 | ✗ (이미 유사) | ApexKey 팔레트에 최근 항목·앱 최근 항목이 있음 |
| 연락처 검색 개선 | ✗ | 제품 범위 밖 |
| 클립보드 30개 | ✗ | ApexKey는 팔레트 통합 기록. 개수 확대는 수요 확인 후 |
| 라이트 모드/테마 정비 | ✗ | ApexKey에 테마·라이트/다크 모드가 이미 있음 |
| fallback 검색 무료화 | ✗ | 범위 밖 |
| 마크다운 표/인용 | ✗ | ApexKey 문서 UI에 표 수요 확인된 바 없음 |
| 온보딩·접근성 개선 | △ | **동결 예외인 "진입장벽 낮추기"에 해당할 수 있음.** 단, 이번 조사만으로 작업을 만들지 않고 사용자 마찰 보고가 있을 때만 |

**결론: 이번 업데이트를 이유로 새 기능·수정 작업을 만들지 않는다.** 제품 동결(2026-10-06)이 그대로 유효하다.

### 4.4 관찰 항목 (다음에 볼 것)

1. **macOS 27 호환** — Alfred 6가 macOS 27 기준으로 환경설정을 개편했다. ApexKey의 macOS 27 실기 동작(특히 테마·글래스·트랙패드)은 별도 확인 가치가 있다.
2. **Alfred UI 생태계** — 워크플로 저자들이 만드는 UI 패턴(데이터 뷰, 진행 바)이 ApexKey의 향후 UI 참고가 될 수는 있다. 채택은 동결 해제 후.
3. **가격** — ApexKey는 무료/MIT라 직접 비교 대상은 아니다. 유료화 논의 때 "£40 일회성"은 시장 기준점으로만 참고.

## 5. 사실/추정 구분

- **사실(공식 문서)**: 버전·날짜·빌드, 기능 목록, 최소 macOS 12, 가격 £40/£70, 무료 업그레이드 조건, DMG 약 6MB, Alfred UI 구조.
- **벤더 주장(미검증)**: "파일 검색이 굉장히 빠르다", "연락처 검색 대폭 향상", "전체적으로 속도 개선".
- **추정**: ApexKey와의 경쟁 영향이 낮다는 판단, 온보딩 개선이 동결 예외에 해당할 수 있다는 판단.

## 6. 미확인·한계

- Alfred 6를 설치해 실제 성능·메모리·macOS 27 동작을 측정하지 않았다.
- 2026년 이전 라이선스의 **할인 업그레이드 금액**은 라이선스 코드를 넣어야 확인된다. 확인하지 않았다.
- Alfred 5 최신 버전(6.0 직전)의 정확한 버전 번호는 이번 조사 범위에서 확정하지 않았다.
- ApexKey의 macOS 27 실기 동작은 이번 조사에서 확인하지 않았다.
