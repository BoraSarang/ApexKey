## 0. 한 줄 결론

**"수정자 + 트랙패드"는 된다. 다만 수정자는 macOS 제스처를 막아 주지 않는다.**
그래서 설계를 두 층으로 나눈다.

1. **에지 슬라이드(1손가락)** — macOS가 쓰지 않는 입력. 수정자로 여러 값을 겹친다.
2. **이산 제스처** — macOS가 이미 쓰는 손가락 수는 쓰지 않는다. 4손가락 탭·5손가락 스와이프만 기본 제공하고, 3/4손가락 스와이프는 **충돌 경고 + 시스템 설정 안내**를 거쳐야 켠다.

---

## 1. 질문에 대한 답 — ⌥ 누른 채 스와이프

### 1-1. 업계에서는 표준이다

| 앱 | 방식 | 근거 |
|---|---|---|
| **BetterTouchTool** | 모든 제스처에 `Trigger only if specific modifier keys are pressed` | 공식 문서 Gesture Configuration |
| **Swish** | 수정자 다층: `generalModifier`·`secondaryModifier`·`tertiaryModifier`·`superModifier`(기본 Fn) | 공식 사이트 + 배포 plist |
| **BTT 사용례** | "같은 3손가락 스와이프를 ⌥/⌘로 다른 동작에 재사용" (Gesture Layering) | 커뮤니티 가이드 |

즉 **"⌥ + 스와이프"는 실재하고 널리 쓰이는 기법**이다. ApexKey에 없는 게 이상한 게 아니라, 지금까지 안 넣은 것이다.

### 1-2. 그러나 수정자는 macOS 제스처를 이기지 못한다

- macOS의 Mission Control/App Exposé/스페이스 전환은 **손가락 수**로 판정한다(3 또는 4, 설정에 따라).
- BTT 사용자 보고: 4손가락 스와이프를 등록해도 **3손가락으로 오인해 Mission Control이 같이 뜬다.** BTT에도 이를 완화하는 옵션이 있지만 해결되지 않는다는 보고가 있다.
- 공식·커뮤니티의 일관된 해법은 **"시스템 설정에서 해당 macOS 제스처를 끈다"**이다.

**따라서 수정자의 올바른 용도는 "OS를 피하는 장치"가 아니라 "우리 앱 안에서 같은 동작에 여러 의미를 겹치는 장치"다.**

### 1-3. ApexKey에 적용하는 4가지 규칙

| # | 규칙 | 이유 |
|:-:|---|---|
| M1 | 수정자는 **정확히 일치**할 때만 규칙이 발동한다 (⌃⌥⇧⌘ 마스크) | 기본 규칙과 ⌥ 규칙이 동시에 뜨는 것을 막는다 |
| M2 | 수정자는 **결정 시점**에 래치한다 (슬라이더=임계값 통과, 스와이프=판정 순간, 탭=손 뗌) | 손을 먼저 대고 키를 늦게 눌러도 된다 |
| M3 | 수정자를 하나라도 누르면 **기본(무수정자) 규칙은 발동하지 않는다** | "⌥를 누르면 원래대로"라는 자연스러운 회피구가 생긴다 |
| M4 | **2손가락 제스처는 만들지 않는다** | 앱들이 ⌘/⌥+2손가락 스크롤(확대·가로 스크롤)에 이미 쓴다 |

> M3 덕분에 기존의 "⌥를 누르면 기능 전체를 건너뛴다" 특례는 **삭제**한다. 별도 규칙이 없는 수정자 조합은 자연히 아무 일도 하지 않는다.

## 2. 왜 다시 만드는가 (요약)

조사 문서의 결론 그대로다.

- 기본값이 **오른쪽 에지 + 2손가락** = macOS 알림 센터와 같은 입력, 2손가락 세로 = 스크롤.
- **0→100%에 풀 스와이프 2.2회**, 최소 1.9초. 빠른 입력은 2스텝에서 폐기.
- 스크롤 억제가 **활성화 이후**에만 켜져 첫 7%에서 페이지가 움직인다.
- 햅틱·포인터 고정·타이핑 가드가 없어 "슬라이더"가 아니라 "숫자 점프"로 느껴진다.

이번 설계는 이 6개를 전부 뒤집는다.

---

## 3. 설계 원칙

| # | 원칙 | 위반 시 |
|:-:|---|---|
| P1 | **OS가 소유한 입력을 건드리지 않는다** | 충돌·오작동 |
| P2 | **들어온 경로로 판정한다** (정지 위치가 아니라) | 손을 갖다 대야 함 |
| P3 | **이동 = 값** (연속, 전 구간) | 감도 병목 |
| P4 | **손을 떼면 즉시 멈춘다** (관성·잔여 없음) | 제어감 상실 |
| P5 | **실패해도 원상복구된다** (스크롤·커서·억제) | 앱 신뢰 상실 |

P5는 타협 불가다. 비공개 프레임워크가 죽어도, 앱이 강제 종료돼도 스크롤과 커서는 돌아와야 한다.

## 4. 입력 공간 지도 — 무엇이 비었나

| 입력 | macOS 점유 | 판정 |
|---|---|---|
| 1손가락 이동 | 커서 | **에지에서만** 가로챈다 (진입 궤적 + 방향 잠금 + 커서 고정) |
| 1손가락 + ⌥/⌃/⌘/⇧ | 없음 | **자유** — 에지 슬라이더 레이어 |
| 2손가락 세로 | 스크롤 | 사용 금지 |
| 2손가락 가로 | 페이지 전환 | 사용 금지 |
| 2손가락 오른쪽 에지 | 알림 센터 | 사용 금지 |
| 2손가락 탭 | 보조 클릭 | 사용 금지 |
| 3손가락 탭 | 찾아보기(기본) | 조건부 |
| 3손가락 스와이프 | Mission Control/Exposé/스페이스 | **충돌** — 경고 후 켬 |
| 4손가락 스와이프 | 위와 동일(설정) | **충돌** — 경고 후 켬 |
| **4손가락 탭** | **없음** | **자유** |
| **5손가락 탭/스와이프** | **없음** | **자유** |

→ 기본 제공은 **에지 슬라이더 + 4손가락 탭 + 5손가락 스와이프**.
→ 3/4손가락 스와이프는 "고급"으로 두고, 켤 때 충돌 배지를 보여 준다.

## 5. 제안 모델 — 두 채널

### 5-1. 채널 A: 에지 슬라이드 (연속)

**트리거**: 손가락 1개가 **패드 밖에서 가장자리로 들어와**, 가장자리를 따라 움직인다.

| 단계 | 판정 | 출력 |
|---|---|---|
| 진입 | 첫 접점이 에지 띠(폭 7%) 안 | 세션 시작, 커서 위치 기억 |
| 이동 시작 | 축 방향 이동 ≥ 0.4% | 스크롤 억제 ON (손을 얹고만 있을 때는 OFF) |
| 방향 잠금 | 진행 방향이 축 방향 우세 (`|축| ≥ 1.2 × |직교|`) | 아니면 즉시 취소(커서 이동으로 양보) |
| 활성 | 축 방향 누적 ≥ 1.5% (≈1.5mm) | `.activated`, 커서 고정, 햅틱 1회 |
| 이동 | 매 프레임 이동량 × 감도 | `.valueDelta` (연속) |
| 종료 | 손 뗌(count 0 프레임) · 손가락 수 변화 · 띠 이탈 · 0.5초 프레임 끊김 | `.deactivated`, 억제 OFF, 커서 복원 |

**핵심 차이 3개**
1. **진입 판정** — 손가락이 패드 안에서 시작해 에지로 걸어오면 **시작하지 않는다**. 밖에서 들어온 경우만 인정. (Margin·Fringe 방식)
2. **방향 잠금** — 커서를 에지 근처로 옮기는 동작과 구분한다.
3. **최근접 추적** — 슬라이드 중 손바닥·엄지가 얹혀도 **기존 손가락을 계속 따라간다** (평균 위치가 아니라 최근접 접점).

**수정자 레이어** (규칙 단위로 설정)

| 예 | 대상 |
|---|---|
| 1손가락 · 오른쪽 에지 | 볼륨 |
| ⌥ + 1손가락 · 오른쪽 에지 | 밝기 (P1, 현재 비활성) |
| ⌃ + 1손가락 · 오른쪽 에지 | 키보드 백라이트 (P1) |

**⇧는 규칙이 아니라 전역 미세 조정**: 슬라이드 중 ⇧를 누르면 이동량 ×0.25 (4배 정밀). Ledge가 쓰는 검증된 패턴이다.

### 5-2. 채널 B: 이산 제스처 (탭·스와이프)

| 기본 제공 | 손가락 | 수정자 | 비고 |
|---|---|---|---|
| 탭 | 4 | 없음 | 자유 공간 |
| 스와이프 좌/우 | 5 | 없음 | 자유 공간 |
| (고급) 탭 | 3 | 없음 | 찾아보기 끄면 자유 |
| (고급) 스와이프 | 3/4 | ⌥⌃⌘⇧ | **충돌 경고 필수** |

수정자 레이어는 같은 물리 동작에 최대 5가지 의미(없음/⌥/⌃/⌘/⇧)를 준다. 단 **M3**에 따라 무수정자 규칙과 수정자 규칙은 배타적이다.

### 5-3. 하지 않는 것

- 2손가락 제스처 (스크롤·페이지 전환과 충돌)
- 1손가락 탭/스와이프 (클릭·드래그와 충돌)
- "⌥ = 기능 끄기" 특례 (M3로 대체)
- 제스처 통계·자동 학습 (제품 동결)

## 6. 인식 알고리즘 명세

### 6-1. 세션

```
idle --(첫 접점, 진입 조건 충족)--> tracking
tracking --(방향 잠금 + 1.5% 이동)--> active
active --(종료 조건)--> idle
tracking --(0.5초 프레임 끊김 또는 띠 이탈)--> idle
```

- 세션은 **접점이 0 → 1이 되는 순간** 시작한다. 그 프레임에서만 진입을 심사한다.
- 진입 실패 세션은 접점이 모두 사라질 때까지 재심사하지 않는다 (에지로 걸어온 커서 이동을 붙잡지 않기 위해).
- 세션 동안 수정자 마스크를 1회 래치한다 (M2).

### 6-2. 파라미터 (권장 기본값)

| 파라미터 | 신규 기본값 | v0.33 | 근거 |
|---|---|---|---|
| 손가락 수 | **1** | 2 | OS 충돌 제거 |
| 에지 띠 폭 | **0.07** | 0.15 | Ledge 기본 7% |
| 시작 임계값 | **0.015** | 0.07 | Ledge 1mm |
| 값 매핑 | **연속** | 이산 14%당 1/16 | P3 |
| 전 구간 이동량 | **1.0 × 감도** | — | 풀 슬라이드 1회 |
| 감도 | **1.5** | 1.0 | 0.67 슬라이드 = 100% |
| 미세 조정 | **⇧ ×0.25** | — | Ledge 패턴 |
| 스크롤 억제 | **이동 시작(0.4%) 즉시** | 활성 후 | P5 |
| 햅틱 | **1/16마다** | 없음 | Ledge·Fringe |
| 포인터 | **고정·복원** | 없음 | 1손가락 필수 |
| 터치 해제 | **count 0 프레임 즉시** | 0.5초 추정 | 손을 떼면 즉시 종료 |
| 프레임 끊김 워치독 | **0.5초** | 없음 | 억제·커서 누수 방지 |

`cooldown`·`stepDistance`·`ignoreThumb`는 **스텝 모드(고급)에서만** 의미가 있다. 기본 UI에서 숨긴다.

### 6-3. 볼륨 적용 — 절대값 방식

프레임마다 `current()`를 읽고 더하면 오차가 누적되고 CoreAudio 호출이 잦아진다. 대신:

```
활성화 시: base = SystemVolume.current()
이동 시:   target = clamp(base + travel)
           |target - lastApplied| ≥ 0.005 일 때만 set(target)
종료 시:   없음 (마지막 값 유지)
```

스텝 모드·단축어 대상은 기존 증분 방식을 유지한다. 단축어는 `1/16` 누적마다 1회 실행한다(연속 모드에서 프레임마다 실행 금지).

### 6-4. 햅틱

- 활성화 순간: 가벼운 1회 (`NSHapticFeedbackManager .generic`)
- 값이 1/16 경계를 넘을 때마다: 1회
- 0%/100% 도달: 1회 강조
- 최대 30Hz로 제한

### 6-5. 포인터 고정

1손가락 슬라이드는 커서를 움직인다. 그대로 두면 슬라이드할 때마다 포인터가 화면을 가로지른다.

```
진입 수락 → 위치 저장
활성화   → CGAssociateMouseAndMouseCursorPosition(false) + 커서 숨김
종료     → CGWarpMouseCursorPosition(저장 위치) + 재연결 + 커서 표시
```

복원은 **모든 경로**에서 보장한다: 정상 종료 · 취소 · 엔진 정지 · 프레임 끊김 · 앱 종료 통지 · 5초 워치독. `PointerAnchor` 타입으로 격리하고 `restore()`는 멱등하게 만든다.

## 7. 안전장치 (P5)

| 상황 | 처리 |
|---|---|
| 프레임 0.5초 끊김 | 억제 해제, 포인터 복원, 인식기 초기화 |
| 브리지 `unavailable` | 동일 (기존 코드 유지) |
| 규칙 삭제/수정 | 활성 슬라이더 즉시 종료 |
| 마스터 토글 OFF | 억제·포인터·HUD 전부 해제 |
| 앱 종료 | `applicationWillTerminate`에서 강제 복원 |
| 포인터 복원 실패 | 5초 워치독이 재시도 |

억제는 **항상** "인식기 상태가 idle이면 OFF"를 불변식으로 둔다. 플래그를 켜는 곳보다 끄는 곳을 더 많이 둔다.

## 8. 설정 UI 재설계

지금은 슬라이더 하나에 손잡이가 7개다(폭·임계값·쿨다운·감도·반전·엄지·억제). 사용자가 튜닝할 수 없다.

### 8-1. 기본 화면

```
[트랙패드]  ● 켜짐

  ┌ 라이브 미리보기 ────────────────┐
  │  오른쪽 에지 ▮  볼륨 42%         │
  │  상태: 대기 / 추적 / 조절 중     │
  └─────────────────────────────────┘

  규칙
  · 오른쪽 에지 · 1손가락 · 볼륨      [편집]
  [+ 규칙 추가]  [권장 설정 불러오기]
```

### 8-2. 규칙 편집 — 필수 4개만

| 항목 | UI |
|---|---|
| 에지 | 4방향 세그먼트 |
| 손가락 | 1 / 2 (2는 "고급" 경고) |
| 대상 | 볼륨 / 단축어 |
| 수정자 | ⌃⌥⇧⌘ 칩 (다중 선택, "없음" 가능) |
| 감도 | 슬라이더 1개 (0.5–3.0) |

**고급** 접기: 폭·임계값·쿨다운·반전·엄지 무시·스크롤 억제·매핑(연속/스텝).

### 8-3. 충돌 배지

3/4손가락 스와이프 규칙을 만들면:

> ⚠ macOS의 Mission Control과 겹칩니다. 시스템 설정에서 해당 제스처를 끄지 않으면 둘 다 실행됩니다. [시스템 설정 열기]

`x-apple.systempreferences:com.apple.Trackpad-Settings.extension` 딥링크 사용.

현재 설정을 읽을 수 있으면(`com.apple.AppleMultitouchTrackpad`의 `Trackpad*SwipeGesture` 키) 배지를 **실시간**으로 바꾼다. 인코딩이 버전마다 다를 수 있으므로, 확실하지 않으면 "확인 필요"로만 표시하고 단정하지 않는다.

### 8-4. 빈 상태

규칙이 0개면 자동 시드하지 않는다(사용자가 지운 것을 존중). 대신 **"권장 설정 불러오기"** 버튼을 크게 둔다. 현재 저장소가 이 상태다(`pref.trackpad.sliders = []`).

struct EdgeSliderRule {

`GestureRule`에도 `modifiers` 추가.

### 9-2. 하위 호환

- 신규 필드는 **커스텀 `init(from:)` + `decodeIfPresent`**로 읽는다. 기존 JSON에 키가 없어도 디코드가 깨지지 않아야 한다(롤백 안전).
- 구버전 규칙의 `mapping` 기본값은 `.stepped` (있던 동작 유지).
- `trackpadTuningVersion`을 **3**으로 올린다.
  - v2 시드 프로필 그대로인 규칙만 → 신규 프로필(1손가락·7%·1.5%·감도 1.5·연속)로 변환.
  - 사용자가 값을 만진 규칙은 **건드리지 않는다**.
  - 규칙이 0개면 아무것도 만들지 않는다(빈 상태 UI로 안내).

### 15-4. 알려진 한계

- **진입 띠 7%** — 손가락이 띠 밖(패드 안쪽)에서 시작하면 동작하지 않는다. 이는 의도된 동작이며(커서 이동과 구분), 폭은 규칙별 고급 설정에서 4~25%로 조절할 수 있다.
- **macOS 제스처와의 충돌** — 수정자를 눌러도 OS 제스처는 그대로 동작한다. 3/4손가락 스와이프 규칙은 배지로 경고하고 시스템 설정 딥링크를 제공한다.
- **밝기 대상** — 내장 디스플레이에서 동작한다(`DisplayServices.framework`를 dlopen으로 격리,
  `Trackpad/DisplayBrightness.swift`). 외장 디스플레이처럼 밝기 변경이 불가능한 환경에서는
  규칙 편집 시 경고가 뜨고 실행되지 않는다. 자동 밝기 조절이 켜져 있으면 OS가 값을 덮어쓸 수 있다.
- **비공개 API 의존** — 밝기는 `DisplayServices.framework`(비공개)에 의존한다. macOS 업데이트로
  프레임워크·심볼이 바뀌면 밝기만 비활성되고 앱과 다른 규칙은 정상 동작한다.
- **밝기 실기 확인(B1~B3)** — 2026-11-19 사용자 확인 완료.
