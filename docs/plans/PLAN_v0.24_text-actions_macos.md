# PLAN_v0.24 — 텍스트 액션 11종 구현 (macOS)

> status: **done** · 2026-09-29 · T-171

## 왜 이것을 골랐나

인계 문서의 2·3·4순위를 처리한 뒤 남은 백로그를 실제로 검증했다.
후보 중 **P1 순수 로직 11종**을 택했다. 이유는 세 가지다.

1. **실제로 미구현이었다.** 11종 전부 `ActionType`에는 있지만 구현이 0이었다 —
   카탈로그에 "준비 중"으로 노출되다가 T-159에서 선택까지 막혔다. 즉 "125종 미구현"
   이라는 문서화된 품질 문제의 일부를 실제로 줄인다
2. **위험 대비 가치가 가장 높다.** 순수 로직이라 의존성 0·macOS 14 동작·실행이 메인을
   블로킹하지 않는다. 스레드 모델을 바꾼 바로 다음 세션이라 회귀 위험을 최소화하고 싶었다
3. **완전히 테스트 가능하다.** 파일·네트워크·권한 의존이 없음

반면 `saveContext → Bool`은 값은 좋았지만 **테스트가 불가능했다** — SwiftData 저장
실패를 재현하려 chmod는 소유자에게 통하지 않고, SQLite 배타 락은 실패가 아니라
**무한 대기**를 유발했다. 검증 불가능한 변경보다 검증 가능한 변경이 낫다고 판단했다.

### 설계 판단 3가지

**1. 파라미터를 `target`이 아니라 `actionParameters`에 넣었다.**
`target`은 한 줄이라 "찾을 문자열 → 바꿀 문자열" 같은 2입력을 표현할 수 없다.
`StopShortcutAction`(`E-MAC-UX-9003`)이 이미 확립한 패턴이다.

**2. 실패를 빈 문자열로 뭉개지 않는다.**
`Outcome.failure(사유)`로 "패턴이 잘못됨"·"입력이 비었음"·"숫자가 아님"을 구분한다.
이 구분이 없으면 사용자가 잘못된 정규식을 넣고 빈 결과를 보고 "액션이 고장났다"고
생각한다. 이 코드가 오류를 로그에만 남기고 토스트엔 빈 문자열을 보여주던 것과
같은 문제다.

**3. 전용 설정 UI를 함께 넣었다.**
`implemented`인 액션은 카탈로그에서 **선택된다.** `DefaultSettingsView`로 두면
"정규식"을 골라도 패턴을 입력할 곳이 없다 — T-159가 고친 "선택은 되지만 쓸 수 없는"
상태가 되돌아온다.

### 한 번 되돌린 결정

숫자→읽기를 처음엔 한국어 단위어(만/억/조)로 직접 구현했다. **현지화 가드가
걸렸고, 그것이 더 나은 신호였다** — 한국어 하드코딩은 (a) 영어 로케일에서 엉뚱한 값이
나오고 (b) 가드를 통과시키려고 예외를 늘려야 한다. `NumberFormatter.spellOut`으로
바꾸니 로케일 처리가 무료로 되고 코드가 줄었다.

| 테스트 | 내용 |

| `testTextActionsStayImplemented` | 역방향 가드 — 정의를 되돌려도 "준비 중"으로 숨기지 않게 |

**변환 테스트(실측)**: `executeStep`의 텍스트 case를 지우면 배선 테스트 2개가
실패한다(21 assertion). 카탈로그 정합성 가드도 11종 때문에 실제로 실패했다 —
그 목록을 빼고 역방향 가드를 추가했다.

### 이 작업에서 드러난 함정 2가지

- **`$1`은 중첩 클로저에서 스코프가 다르다.** `updateConfig { $0.x = $1 }` 안에
  바인딩 setter 클로저가 겹치면 컴파일 에러가 난다. 명시적 이름을 쓴다
- **비결정적 테스트**: 클립보드 테스트를 "빈 클립보드에서 get이 성공하는가"로
  쓰면 사용자의 클립보드 상태에 따라 흔들린다. set을 먼저 하고 원본을 복원해야 한다
