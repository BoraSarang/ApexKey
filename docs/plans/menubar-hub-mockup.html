동작 변경표 — 지금 vs 제안 (코딩 전 확인용)

구분지금 (AppDelegate+Menus.swift:111-122)제안 (PickBeon 패리티)
좌클릭togglePanel() — 900×620 메인창 열기/닫기 토글 + 포커스 탈취Hub 팝오버 열기 (360×~500, transient — 바깥 클릭で 닫힘). 실수 클릭 피해 ↓
우클릭NSMenu (열기/아이콘/정보/설정…/종료)레거시 NSMenu 유지 (폴백) 또는 디버그로 — 우클릭 의존 제거가 목적이므로 유지 권장
"열기" 메뉴togglePanelAction → 토글 (이름과 동작 불일치)"메인 창 열기 ⌘O" — open-only (이미 열려 있으면 앞으로만, 절대 닫지 않음). 닫기는 Esc/⌘W
창 크기NSPanel 900×620 중앙Hub는 메뉴바 앵커 팝오버로; 메인창은 Hub 안 "메인 창 열기"에서만
구현—신규 MenuHubView.swift (SwiftUI) + NSPopover(.transient, 360×512) + hubAction 닫기-후-실행 — PickBeon MenuPopupView.swift / PickBeonApp.swift:29-50 구조 그대로 이식.
왜 토글이 짜증나는지: 메뉴바 아이콘은 "상태 확인/빠른 실행" 심리적 모델인데, 지금은 매 클릭마다 거대 창 + NSApp.activate로 작업 포커스를 뺏음. PickBeon은 이 문제를 작은 transient 팝오버 + 모든 행 액션 후 자동 닫힘(coordinator.menuAction { dismissMenu?(); work() })으로 해결 — ApexKey도 동일 패턴 권장.
최소안(B): Hub 없이 좌/우만 맞바꾸고 열기를 open-only로 — 10줄 수정으로 당장 가능. Hub는 그 다음 단계.
