## 2. PR #7 병합 (완료) — 리뷰만 남음

### 무슨 일이 있었나

`fix/macos-audit-p0` → `main` **PR #7**로 v0.4~v0.27 (59커밋)이 병합됐다
(`3664d99`). 기존 PR #6(`feat/macos-p0-critical-fixes`, 20커밋)의 커밋을 전부
포함하고 있어, GitHub이 #6도 자동으로 MERGED 처리했다.

**병합 방식**: `Merge pull request #7` 병합 커밋 — main의 기존 관례를 따랐다.
squash하지 않은 이유는 **각 커밋에 회귀 테스트가 붙어 있어** 커밋 단위로 읽어야
그 테스트가 어떤 버그를 막는지 보이기 때문이다.

### 남는 것

- [ ] **커밋 단위 리뷰** — 59커밋을 한 번에 올렸다. squash 하지 않았으므로
      가능하지만 시간 투자다. 리뷰가 필요하다면 `PLAN_v0.21`~`PLAN_v0.26`부터
- [ ] **릴리스 태그는 아직 안 붙였다.** 붙이면 `release.yml`이 돌아간다.
      T-166 결정대로 **무서명** 릴리스이며 버전업마다 권한 재승인이 필요하다
      (README·릴리스 노트에 고지돼 있음)


## 3. macOS 14 런타임 실기 검증

### 왜 남았나

배포 타깃은 macOS 14지만 **이 작업은 macOS 26에서만 수행됐다.**
v0.3.2에서 SwiftUI 빈 윈도우를 근본 제거했지만 14 실기는 여전히 안 했다.

영향: macOS 14에서만 나는 API 차이, SwiftUI 차이, 권한 프롬프트 차이.

### 완료 기준

- [ ] macOS 14 기기 또는 가상머신에서 `~/Applications/ApexKey.app` 실행
- [ ] 핫키 등록·메뉴 열거·접근성 권한 1회성 통과
- [ ] §8-1(7건)·§8-2(5건) 최소 확인

## 4. `error_message_ko.json` 규칙 조율

### 왜 남았나

`~/.config/opencode/rules/quality.md`는 사용자 메시지를 `error_message_ko.json`에
두라고 요구하지만 **그 파일이 존재하지 않는다.** 현재는 `Localizable.strings`의
`error.user.*` 키가 en까지 포함해 있어 기능적으로 우월하다.

`~/.config/opencode/rules/`는 **프로젝트 밖**이라 **사용자 지시 없이 수정하지 않는다.**

### 선택지

- (a) `rules/quality.md`에 "ko/en 통합 strings를 쓴다"는 **예외 조항 추가** ← 이전 권장
- (b) `error_message_ko.json` 신설

### 완료 기준

- [ ] 사용자가 (a)/(b) 결정
- [ ] 그에 따라 반영
