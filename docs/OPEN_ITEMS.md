## 1. 사용자 실동작 검증 72건

### 왜 남았나

에이전트가 대신할 수 없다. 핫키 등록·접근성 권한·TCC·스레드 반응성은
**사용자가 실제로 조작해야만** 확인할 수 있다. macOS 14 실기 기기도 없다.

세부 항목은 [`FUNCTIONAL_CHECKLIST.md`](FUNCTIONAL_CHECKLIST.md) §8에 있고,
여기서는 집계만 한다. **중복 체크를 만들지 않기 위해 세부는 옮기지 않는다.**

| 절 | 건수 | 내용 | 위험도 |
|---|:-:|---|:-:|
| 8-1 | 7 | 핫키 | 🟢 |
| 8-2 | 5 | 메뉴 명령 (AppleScript 경로) | 🟡 |
| 8-3 | 4 | 자동화 | 🟡 |
| 8-4 | 5 | 테마 / 설정 | 🟢 |
| 8-5 | 4 | 스크립트 | 🟡 |
| 8-6 | 5 | 단계 저장 / 실행 | 🟡 |
| **8-7** | **8** | **실행 백그라운드화 (T-170)** | 🔴 |
| **8-8** | **14** | **텍스트/데이터 액션 23종 UI (T-171·T-172)** | 🟡 |
| 8-9 | 5 | 키 입력·HTML→Markdown 3종 UI (T-179) | 🟡 |
| 8-10 | 4 | blob 복구 + 저장 debounce (T-175·T-176) | 🟢 |
| **8-11** | **5** | **Menu HUD 드릴인·앵커 (v0.29)** | 🟢 |
| **8-12** | **6** | **메뉴바 아이콘 그리드 (v0.29)** | 🟡 |

합계 7+5+4+5+4+5+8+14+5+4+5+6 = **72건**.

### 완료 기준

- [ ] §8 전체 72건 확인 (`FUNCTIONAL_CHECKLIST.md`에서 직접 체크)
- [ ] **8-7 8건이 특히 중요하다.** 스레드 모델을 바꿨다(T-170). 특히
      **사이보그 모드 `⌘⇧↩` 해제**와 **자동화 트리거 발동**이 위험하다 —
      직렬 큐 변경 + `shortcutProvider` 메인 홉의 영향을 가장 직접적으로 받는다.
      2026-10-02에 홉 방식이 바뀜(async+타임아웃) — 재확인 필요

## 3. macOS 14 런타임 실기 검증

### 왜 남았나

배포 타깃은 macOS 14지만 **이 작업은 macOS 26에서만 수행됐다.**
v0.3.2에서 SwiftUI 빈 윈도우를 근본 제거했지만 14 실기는 여전히 안 했다.

영향: macOS 14에서만 나는 API 차이, SwiftUI 차이, 권한 프롬프트 차이.

## 4. `error_message_ko.json` 규칙 조율

### 왜 남았나

`~/.config/opencode/rules/quality.md`는 사용자 메시지를 `error_message_ko.json`에
두라고 요구하지만 **그 파일이 존재하지 않는다.** 현재는 `Localizable.strings`의
`error.user.*` 키가 en까지 포함해 있어 기능적으로 우월하다.

`~/.config/opencode/rules/`는 **프로젝트 밖**이라 **사용자 지시 없이 수정하지 않는다.**

### 선택지

- (a) `rules/quality.md`에 "ko/en 통합 strings를 쓴다"는 **예외 조항 추가** ← 이전 권장
- (b) `error_message_ko.json` 신설

### 완료 기준

- [ ] 사용자가 (a)/(b) 결정
- [ ] 그에 따라 반영

## 5. `docs/plans/` 정리 — **하지 않기로 함**

### 왜 남겨 두나

각 `PLAN_*.md`에 `status:`가 이미 있다. 완료된 계획은 읽지 않으면 그만이다.
파일 수가 많아 보이지만 **색인이 필요할 뿐 정리가 필요하지 않다.**

정리(삭제·이동)하면 이력의 맥락이 사라지고 되돌리기도 어렵다.
`docs/README.md`가 "완료된 계획은 status부터 본다"로 안내하는 것으로 충분하다고
판단했다.

### 완료 기준

- [ ] 이 결정을 **유지하기로 확인** (여기 체크하면 정리가 아니라 결정 유지)
